# Заявки с лендинга «Тревога»

Страница `/trevoga/` размещается на GitHub Pages. Она отправляет JSON через `POST` на отдельную функцию Yandex Cloud. Функция проверяет заявку и передаёт её в личный чат Telegram через бота. Токен бота и ID чата находятся только в переменных окружения функции.

## Подключение

1. Создать бота через [@BotFather](https://t.me/BotFather) и написать ему `/start` со своего Telegram-аккаунта.
2. Узнать ID личного чата из ответа `getUpdates` Telegram Bot API. Не публиковать токен в GitHub, файлах сайта или переписке.
3. В Yandex Cloud создать Cloud Function на Python с кодом `yandex_function/index.py`, точка входа `index.handler`. Установить переменные окружения `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` в настройках версии функции. Включить публичный HTTP-вызов, чтобы браузер мог отправлять заявки.
4. После проверки политики обработки персональных данных и реквизитов оператора вставить URL функции в атрибут `data-endpoint` формы в `/trevoga/index.html`.
5. Отправить одну тестовую заявку с опубликованного домена `https://anastasiamedvedeva.ru/trevoga/`, убедиться, что сообщение пришло в Telegram и сайт показал успешную отправку. Проверить также ошибку отправки.

Функция принимает запросы с `https://anastasiamedvedeva.ru`, проверяет обязательные поля, ограничивает размер сообщения, игнорирует поле-ловушку для простых ботов и не пишет содержимое заявок в лог. Это не полная защита от спама; при большом потоке заявок стоит добавить ограничение частоты запросов на уровне инфраструктуры.

Поскольку свободное поле может содержать сведения о здоровье, перед включением формы нужно завершить политику обработки персональных данных и решить, допустима ли передача полного текста заявки в Telegram. При необходимости функцию можно изменить так, чтобы в Telegram приходило только уведомление, а данные хранились в выбранной системе.

Проверка кода: `python3 -m unittest discover -s trevoga/backend/yandex_function -p 'test_*.py'` из корня сайта.
